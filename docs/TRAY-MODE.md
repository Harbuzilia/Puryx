# Трей-режим и фоновая проверка обновлений

ROADMAP v3.1, День 13, фаза A. Документ фиксирует семантику, которую выбрал
проект: одна опция — одно поведение, закрытие окна — всегда выход.

## Поведение окна

| Действие пользователя | Настройка `MinimizeToTray` | Результат |
|---|---|---|
| Кнопка «Свернуть» | выключена (по умолчанию) | окно уходит в панель задач |
| Кнопка «Свернуть» | включена | окно скрывается, приложение живёт в трее |
| Закрытие окна (X) | любая | приложение завершается |
| Меню трея → «Выход» | любая | приложение завершается |

Опция `MinimizeToTray` управляет **только** кнопкой «Свернуть». Кнопка X
никогда не сворачивает в трей: пользователь, закрывший окно, ожидает выхода, а
не «процесс, который остался жить». Это осознанный отказ от «свернуть в трей при
закрытии» — меньше сюрпризов и одна настройка вместо двух.

## Иконка и меню

- Иконка создаётся после показа главного окна (`TrayService.Initialize`).
- Двойной клик по иконке — показать окно.
- Контекстное меню: «Открыть Puryx», разделитель, «Выход».
- Иконка берётся из `app.ico` рядом с exe (копируется сборкой), иначе — иконка
  исполняемого файла, иначе — системная заглушка. Сбой загрузки иконки не роняет
  старт приложения.

## Фоновая проверка обновлений

Опция `AutoCheckUpdates` **выключена по умолчанию**: сеть затрагивается только
после явного согласия пользователя.

Когда включена:

0. Первая проверка — через **30 секунд** после старта (не бьёт по запуску).
0. Интервал — **не чаще одного раза в 24 часа**; отметка последней проверки
   (`update_state.json`, UTC) переживает перезапуски, поэтому частые старты
   приложения не превращаются в частые сетевые запросы.
0. Если с момента последней проверки прошло меньше суток, таймер взводится на
   **остаток интервала**, а не на полные сутки: суточный ритм не сдвигается
   перезапусками.
0. Отметка «последняя проверка» записывается **до** сетевого запроса: сбой сети
   или GitHub не приводит к шторму повторов — следующая попытка через сутки.
0. Отметка в будущем (часы откатили) считается недостоверной: одна проверка
   разрешается и перезаписывает состояние.
0. При наличии новой версии показывается **балун** в трее; клик по нему
   открывает страницу настроек, где установка запускается явной кнопкой.

Чего авто-проверка **не делает**: не скачивает ассет, не проверяет SHA256, не
запускает swap и не перезапускает приложение. Скачивание и установка — только
по явному действию пользователя (День 12). Телеметрии нет; единственный сетевой
запрос — `GET /repos/Harbuzilia/Puryx/releases/latest`.

Переключение опций в настройках применяется на лету, без перезапуска:
`TrayService.ApplyOptions(minimizeToTray, autoCheckUpdates)` пересчитывает
поведение минимизации и взводит/снимает таймер.

## Конфигурация

Оба файла лежат в config-каталоге (`ConfigService.ConfigDirectory`):

- `tray_settings.json` — `MinimizeToTray`, `AutoCheckUpdates`;
- `update_state.json` — `LastAutoCheckUtc` (UTC-момент последней авто-проверки).

## Что покрыто тестами

Чистая логика расписания вынесена в Core и покрыта юнит-тестами
(`AutoUpdateScheduleTests`, 8 тестов): due/не-due, границы интервала, отметка из
будущего, задержка первой проверки, остаток интервала. Persistence опций и
состояния — `TraySettingsTests` (3 теста).

UI-часть (`NotifyIcon`, скрытие окна, балун) юнит-тестами не покрывается —
проверяется смоук-запуском: включить `MinimizeToTray`, нажать «Свернуть»,
убедиться, что процесс жив, а окно невидимо; затем выйти через меню трея.
