# CODE-SIGNING: решение по подписи кода

> Зафиксировано в День 27 плана ([ROADMAP.md](ROADMAP.md), фаза P4 «Продуктизация»). Статус: **v3.0.0 выходит без подписи кода**; покупка сертификата — вне скоупа плана. Решение пересматривается при росте пользовательской базы.

## Контекст

Puryx распространяется как portable exe через GitHub Releases. Исполняемый файл не подписан, поэтому при первом запуске Windows SmartScreen показывает предупреждение «Windows защитила ваш компьютер». Пользователь обходит его один раз: «Подробнее» → «Выполнить в любом случае». Инструкция зафиксирована в [README](../README.md) (Быстрый старт, шаг 2, и примечание SmartScreen в разделе «Сборка и запуск»).

## Опции

### А. Без подписи (текущее состояние — выбрано для v3.0.0)

- Пользователь один раз обходит SmartScreen вручную — инструкция в [README](../README.md).
- Минусы (общеизвестные): предупреждение снижает доверие новых пользователей; неподписанные утилиты «класса чистильщиков» чаще попадают под эвристические срабатывания антивирусов.
- Со временем SmartScreen может смягчить предупреждение по мере накопления репутации файла (механизм репутации Microsoft непубличен — гарантий нет).
- Затраты: нулевые. Подходит проекту без бюджета и юрлица.

### Б. Self-signed сертификат

- Технически ставит подпись, но сертификат не выдан доверенным центром сертификации: цепочка доверия не строится ни на одной пользовательской машине (корень никто не устанавливает в доверенные).
- SmartScreen принимает решение по репутации файла/издателя — самоподписанный сертификат её не создаёт, предупреждение остаётся.
- Практический смысл — только внутренние сценарии: проверка собственного кода верификации подписи, тесты.

**Вывод: не вариант для распространения — не снимает SmartScreen, только добавляет «недоверенного издателя».**

### В. Сертификат подписи кода (OV / EV) или облачная подпись

- **Что даёт:** подпись сертификатом, выданным доверенным CA после проверки издателя. Для OV-сертификатов репутация SmartScreen накапливается со временем (на первых загрузках предупреждение всё ещё возможно). EV-сертификаты исторически связываются с «мгновенной» репутацией SmartScreen — по заявлениям вендоров сертификатов и Microsoft; фактическое поведение — на стороне Microsoft и меняется со временем, проверяйте актуальную документацию.
- **Что требует:** пройденную валидацию в CA (для OV/EV обычно организация-юрлицо; доступность для физических лиц зависит от вендора — уточняйте), оплату (цены здесь не приводим — они меняются, уточняйте у вендоров), хранение закрытого ключа по правилам CA/B Forum (аппаратный токен / HSM) либо облачный сервис подписи, где ключ живёт у провайдера.
- **Облачные платформы подписи** (Azure Trusted Signing, SignPath и другие) снимают проблему с токенами; у некоторых бывают программы для open-source проектов. Условия, доступность и требования для конкретного проекта меняются — уточняйте у вендоров.

**Вывод: правильное долгосрочное решение при росте проекта — сейчас заблокировано отсутствием организации и бюджета.**
